# RankBoard 1.10.6 跨版本兼容性排查

本次排查按「直接构建 → 目标服务端启动 → 网页 HTTP → 离线玩家登录」分层验证。所有服务端测试均在独立临时目录运行，不使用现有世界存档。

## 结果

| 加载器 / Minecraft | 直接构建基线 | 服务端启动 | 网页 HTTP 200 | 玩家登录 |
| --- | --- | --- | --- | --- |
| Fabric 1.21–1.21.11 | 1.21.4 | 12/12 通过 | 1.21.11 复测通过 | 12/12 通过 |
| NeoForge 1.21–1.21.11 | 1.21.4 | 12/12 通过 | 1.21.11 复测通过 | 12/12 通过 |
| Fabric 26.1、26.1.1、26.1.2 | 26.1.2 | 3/3 通过 | 3/3 通过 | 3/3 通过 |
| NeoForge 26.1.x | 26.1.2 | 26.1.2 通过 | 26.1.2 通过 | 26.1.2 通过 |
| Fabric 26.2 | 26.2 | 通过 | 通过 | 未测：客户端协议库尚无 26.2 支持 |
| NeoForge 26.2 | 26.2 | 通过 | 通过 | 未测：客户端协议库尚无 26.2 支持 |
| Fabric 26.3 | 26.3 | 通过 | 通过 | 未测：客户端协议库尚无 26.3 支持 |
| NeoForge 26.3 | 26.3 | 通过 | 通过 | 未测：客户端协议库尚无 26.3 支持 |

1.21.x 测试在每个目标小版本启动独立服务器，并用离线测试玩家登录，停留后正常退出。26.2 和 26.3 使用各自精确的原版/加载器服务器进行启动及网页请求验证；由于当前自动化客户端不识别这两个协议版本，没有把它们记为玩家进服通过。

## 修复内容

此前已发布的 1.10.5 1.21.x 单 JAR 在不同小版本之间存在二进制链接不兼容，1.21.10 登录时曾因引用较新权限 API 的类而崩溃。这次将兼容代码改为按运行时 API 解析，并继续排查到持久化状态、NBT、玩家属性档案、组件查询、注册表键、权限接口和统计标识符在小版本间的变更。完整玩家登录矩阵验证了 1.10.6 的 1.21.x Fabric 与 NeoForge 直接构建包。

## 进服菜单

普通玩家在开启进服榜单提示时仅收到一个可点击的「展开榜单信息」按钮，点击执行 `/leaderboard` 打开完整详情。OP 仍保留原详细菜单及其中的语言、白名单和计分板管理选项。中英文提示键已分别加入语言资源。

## 复测脚本

- `scripts/smoke-fabric-direct.ps1`：使用隔离目录逐版本启动 Fabric 服务端，可检查网页 HTTP，并在客户端协议可用时模拟玩家登录。
- `scripts/smoke-neoforge-direct.ps1`：使用独立的 Gradle 运行目录逐版本启动 NeoForge 服务端，可检查网页 HTTP，并在客户端协议可用时模拟玩家登录。
- `scripts/check-minecraft-class-links.ps1`：针对给定的已映射 Minecraft JAR 做静态类引用检查；它不能代替运行时启动和进服测试。
